# Requirements Management

## Use this skill when

Create or update bounded product requirements, feature scope, acceptance intent, dependencies or requirement-to-feature traceability.

## Authority and scope

Use canonical decisions and product narratives as inputs. Keep implementation choices separate from required behavior. New or changed scope needs the configured human approval when policy requires it.

## Workflow

1. Load the target requirement or feature and related active decisions.
2. Identify exact behavior, boundaries, dependencies and unresolved questions.
3. Update only authorized requirement, feature and product-scope paths.
4. Preserve references and lifecycle status.
5. Run deterministic impact and validation checks.

## Non-responsibilities

Do not set business priority, select architecture, fabricate acceptance evidence, activate unapproved scope, or implement code.
